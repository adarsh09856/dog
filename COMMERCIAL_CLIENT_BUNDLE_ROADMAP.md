# Kodewaves platform delivery roadmap

Updated 26 October 2026. Worktree: `codex/client-bundle-theme`. This is the ordered execution plan for the current shared-platform and commercial client-bundle scope. It is not a completion claim. Voice-flow implementation remains in the other chat's checkout; preserve that checkout and branch until its owner reports completion.

## Outcome

Ship one production-ready platform where (1) SaaS owner control and client installation boundaries are enforced server-side, (2) public, user and admin surfaces share the configured brand and theme, (3) voice conversations work across browser and phone in Hindi, English and Hinglish without repeated, irrelevant, cut or overlapping speech, and (4) a client-only bundle can be licensed, installed, updated and recovered without exposing owner secrets.

## How to use this plan

- Execute phases in order; a later phase may be developed in parallel only if it does not depend on an unfinished interface or branch.
- “Implemented” means source exists. “Code verified” means focused automated checks passed. “Accepted” requires the real user journey and failure handling below. Never promote a status based on a local source test alone.
- Every phase closeout records commit, exact command/result, deployment/build identity, test/run IDs, and remaining exceptions in the linked tracker.
- Keep changes isolated in the current worktree. Integrate the voice-flow branch using a dedicated integration worktree after it is complete; do not switch or reset either active checkout.
- Do not run paid-provider probes or place telephone calls until browser audio passes. The user previously authorized an outbound test to `6366458170` and identified inbound number `+1 350 900 1419`; use only after the browser gate and report call evidence.
